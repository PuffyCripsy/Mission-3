> **과제**: 자동화 도구 비교 구현 (프로젝트 1) + 자유 주제 자동화 설계 (프로젝트 2)  
> **작성일**: 2026년  7월 28일
> **사용 도구**: n8n, Make (Integromat)

---

## 1. 자동화 업무 정의

### 📌 업무명
**도서 구입 신청서 자동 처리 시스템**

### 📌 배경 및 문제 상황
- 직원들이 Google Form으로 도서 구입을 신청함
- 담당자가 매번 수동으로 신청 내용을 확인하고 이메일을 보내야 함
- **5만 원 이상** 도서는 담당자 승인이 필요하지만, 알림이 누락되는 경우 발생
- **5만 원 미만** 도서는 신청자에게 접수 확인 메일을 보내야 하지만 지연되는 경우 있음

### 📌 자동화 목표
| 구분 | 기존 방식 | 자동화 후 |
|------|-----------|-----------|
| 신청 확인 | 담당자가 수동 확인 | 즉시 자동 감지 |
| 이메일 발송 | 수동 작성 및 발송 | 자동 발송 |
| 처리 시간 | 수 시간 ~ 수일 | 수 초 이내 |
| 누락 위험 | 높음 | 없음 |

## 3. 각 단계 상세 설명

### 🟦  트리거 및 연동 방식 (Trigger & Integration)

| 항목 | 내용 |
| :--- | :--- |
| **트리거 (Trigger)** | **Google Sheets - Watch New Rows** |
| **연동 방식** | **폴링 (Polling)** 방식 (15분 간격 실행) |
| **데이터 흐름** | Google Forms → Google Sheets (저장) → Make (감지) |
| **설명** | 구글 폼 응답이 시트에 기록되면, Make가 15분마다 새 행을 감지하여 데이터를 가져오는 간접 연동 구조. 데이터 아카이빙과 안정적인 처리가 가능. |

**Google Form 필드 구성:**

① 신청자 이름     (단답형)
② 도서명          (단답형)
③  도서 가격 (원)  (숫자형)
④ 신청자 이메일   (단답형 / 이메일 형식)


---
### 🟦 FILTER / ROUTER — 조건 분기 설정

라우터(Router)를 통해 금액 기준 및 데이터 유효성(이메일 존재 여부)에 따라 경로를 최적화함.

| 경로 | 필터 조건 (Filter Conditions) | 실행 액션 (Action) |
| :--- | :--- | :--- |
| **1st 경로 (YES)** | `Price` **Greater than or equal to** `50000` | 담당자 승인 요청 이메일 발송 |
| **2nd 경로 (NO)** | `Price` **Less than** `50000` <br> **AND** `Email` **Exists** | 신청자 접수 확인 이메일 발송 |

#### 💡 필터 설계 의도
* **금액 기준 분기:** 5만 원을 기준으로 담당자 승인 프로세스와 단순 접수 확인 프로세스를 이원화함.
* **이메일 유효성 검사 (Exists):** 5만 원 미만 건(NO 경로)의 경우, **신청자의 이메일 주소가 존재하는 경우에만** 발송 로직이 작동하도록 설계하여, 데이터 누락으로 인한 메일 발송 에러를 사전에 방지.


### 🟥  액션 상세 내용 (Action Details)

### **[Action 1] 담당자 승인 요청 (ID: 5)**
*   **대상:** 내부 회계 담당자 (고정 수신자)
*   **목적:** 고액 신청 건에 대한 관리자 검토 및 승인 유도
*   **주요 내용:** 신청자 이름, 신청 금액, 상세 사유 등 시트 데이터 매핑

### **[Action 2] 신청자 접수 확인 (ID: 6)**
*   **대상:** `신청자 이메일` (동적 수신자)
*   **목적:** 소액 신청 건에 대한 즉시 접수 알림 및 고객 경험 향상
*   **주요 내용:** 접수 완료 안내 및 신청 금액 확인 문구 포함

---
#### 💡 기대 효과
1. **업무 효율화:** 단순 접수 확인 업무의 100% 자동화로 수기 작업 시간 단축
2. **오류 방지:** 필터링 로직을 통한 잘못된 데이터 처리 방지
3. **체계적 관리:** 금액별 승인 프로세스 이원화로 내부 통제 강화

### 📊 비교 분석표

| 비교 항목 | n8n | Make |
|-----------|-----|------|
| **UI/UX** | 노드 기반 캔버스, 개발자 친화적 | 시각적 버블 UI, 직관적 |
| **설정 난이도** | 중간 (초기 설정 필요) | 낮음 (가이드 친절) |

### ✅ 각 도구 장단점

#### 1. n8n의 주요 장점 (Pros)
| 장점 | 상세 설명 |
| :--- | :--- |
| **💰 압도적인 가성비** | 직접 설치(Self-hosting) 시 실행 횟수 제한 없이 무료/저비용으로 무제한 사용 가능 |
| **🔒 강력한 보안** | 데이터가 외부 클라우드가 아닌 내 서버에서만 처리되어 개인정보 보호에 유리 |
| **🛠️ 높은 자유도** | JavaScript 코드를 직접 작성할 수 있어 복잡한 로직 구현이 가능 |
| **📈 시각적 흐름** | 노드 기반 인터페이스로 데이터의 흐름을 한눈에 파악하고 디버깅하기 쉬움 |

#### 2. n8n의 주요 단점 (Cons)
| 단점 | 상세 설명 |
| :--- | :--- |
| **⚙️ 초기 설정 난이도** | 서버 구축, 도커(Docker) 등 기초적인 IT 지식이 있어야 설치 및 운영 가능 |
| **⚠️ 유지보수 책임** | 서비스 장애 발생 시 사용자가 직접 서버를 체크하고 해결해야 함 |
| **🧠 학습 곡선** | JSON 데이터 구조에 대한 이해가 필요하여 초보자에게는 다소 어려울 수 있음 |
| **🔌 앱 연동 개수** | Zapier 등 대형 유료 툴에 비해 공식 지원하는 앱의 종류가 적을 수 있음 |

#### 1. Make의 주요 장점 (Pros)
| 장점 | 상세 설명 |

| **⚡ 강력한 로직 제어** | 라우터, 필터, 이터레이터(반복) 등 복잡한 데이터 처리를 코딩 없이 구현 가능 |
| **☁️ 관리의 편리함** | 별도의 서버 설치 없이 웹에서 바로 사용 가능하며, 실행 이력을 확인하기 매우 쉬움 |

#### 2. Make의 주요 단점 (Cons)
| 단점 | 상세 설명 |
| :--- | :--- |
| **💰 실행 횟수(Ops) 제한** | 데이터가 한 단계 이동할 때마다 'Ops'가 차감되며, 사용량이 많아지면 비용 부담 발생 |
| **☁️ 데이터 보안 우려** | 클라우드 기반 서비스이므로, 민감한 내부 데이터를 외부 서버에 통과시켜야 함 |
| **🧩 데이터 매핑의 복잡성** | '번들(Bundle)'과 '어레이(Array)' 개념이 있어 초보자가 데이터 구조를 이해하는 데 시간이 걸림 |
| **⏳ 실시간성 제약** | 무료 플랜이나 저가 플랜에서는 데이터 감지 주기(Polling)가 길어질 수 있음 |

## 5. 프로젝트 2 — 자유 주제 자동화

### 📌 선정 업무
**증권가 뉴스 세줄 요약 이메일 발송** 
프로젝트 1과 다른 점: AI Action 추가 (보너스 크레딧 요구사항) 

### 📌 도구 선정: **Make (Integromat)**

**선정 이유:**
1) Zapier 대비 압도적인 가성비와 강력한 다중 분기(Router) 처리
 AI가 요약한 하나의 결과물을 Gmail과 Google Sheets 등 다중 채널로 동시에 분기하여 전송하기 위해 라우터 기능이 필수적인데,  Zapier는 무료 또는 하위 요금제에서 멀티스텝 라우터 기능을 제한하거나 유료 플랜을 요구하는 반면, Make는 기본 플랜부터 강력한 시각적 라우터 기능을 자유롭게 지원하며 실행 비용(Operation) 면에서 경제성이 뛰어남.

2) n8n 대비 비개발자 친화적인 직관적인 시각적 매핑 (Visual Builder)
 n8n은 자바스크립트나 JSON 표현식 등 개발 지식이 요구되는 진입장벽이 있는 반면구글 시트의 날짜와 요약 내용 필드에 동적 데이터({{now}}, AI Result 등을 복잡한 코드 없이 직관적으로 매핑 가능.

3) 실시간 데이터 패킷 추적 및 뛰어난 디버깅 편의성
RSS 수집부터 AI 분석, 라우터를 거쳐 최종 전송되기까지의 데이터 흐름을 실시간으로 검증해야 했는데, Make는 Run once 실행 시 각 모듈별 데이터 패킷과 변수 흐름을 실시간으로 시각화하여 보여주므로, 오류 발생 시 원인 추적 및 디버깅 속도가 다른 툴들에 비해 우수

4) 한 마디로 눈으로 확인하기 쉽고, 비전문가도 사용, 수정, 관리 하기 쉬움.

## 6. 단계별 역할
1. RSS (Watch RSS feed items): 워크플로우를 시작하는 트리거(Trigger)

2. Tools (Text aggregator): 이전 단계(RSS)에서 가져온 여러 데이터나 텍스트 요소들을 하나의 완성된 글이나 프롬프트 형태로 묶어 다음 단계로 전달

3. Google Gemini AI (Generate a response): 구글의 인공지능(AI)을 활용한 데이터 처리 단계로 필터링 된 주식관련 뉴스 3줄 요약

4. Router: 데이터의 경로를 나누어주는 분기점- Action 1 Google Sheets (Add a Row) — 주식관련 뉴스 요약을 지정된 구글 시트 파일에 새로운 행(Row)을 추가하여 내용을 저장(아카이빙)
                                           Action 2 Gmail (Send an email) —  AI가 작성한 내용이나 요약본을 지정된 수신자의 지메일로 전송합니다.

## 7. 핵심 개념 정리

### Trigger (트리거)
> 워크플로우를 **시작시키는 이벤트**
> - 본 워크플로우: Google Form 제출 → 즉시 실행

### Action (액션)
> 트리거 이후 **실제로 수행되는 작업**
> - Action 1: 담당자에게 이메일 발송
> - Action 2: 신청자에게 이메일 발송

### Filter / Router (조건 분기)
> 조건에 따라 **다른 경로로 분기**시키는 구조
> - 조건: `price >= 50000`
> - YES → 담당자 이메일
> - NO → 신청자 이메일
