# 📚 도서 구입 신청 자동화 워크플로우 설계 문서

> **과제**: 자동화 도구 비교 구현 (프로젝트 1) + 자유 주제 자동화 설계 (프로젝트 2)  
> **작성일**: 2025년  
> **사용 도구**: n8n, Make (Integromat)

---

## 1. 자동화 업무 정의

### 📌 업무명
**도서 구입 신청서 자동 처리 시스템**

### 📌 배경 및 문제 상황
- 직원들이 Google Form으로 도서 구입을 신청함
- 담당자가 매번 수동으로 신청 내용을 확인하고 이메일을 보내야 함
- **5만 원 이상** 도서는 담당자 승인이 필요하지만, 알림이 누락되는 경우 발생
- **5만 원 미만** 도서는 신청자에게 접수 확인 메일을 보내야 하지만 지연되는 경우 있음

### 📌 자동화 목표
| 구분 | 기존 방식 | 자동화 후 |
|------|-----------|-----------|
| 신청 확인 | 담당자가 수동 확인 | 즉시 자동 감지 |
| 이메일 발송 | 수동 작성 및 발송 | 자동 발송 |
| 처리 시간 | 수 시간 ~ 수일 | 수 초 이내 |
| 누락 위험 | 높음 | 없음 |

---

## 2. 워크플로우 구조 설계

### 🔷 전체 흐름도

```
[TRIGGER] Google Form 제출
         ↓
[ACTION 1] 응답 데이터 읽기
  - 신청자 이름
  - 신청자 이메일
  - 도서명
  - 도서 가격
         ↓
[FILTER / ROUTER] 가격 조건 분기
  도서 가격 >= 50,000원 ?
         ↓                    ↓
       YES                   NO
         ↓                    ↓
[ACTION 2-A]          [ACTION 2-B]
담당자에게 이메일       신청자에게 이메일
승인 요청 발송         접수 확인 발송
         ↓                    ↓
      [END]               [END]
```

---

## 3. 각 단계 상세 설명

### 🟦 TRIGGER — Google Form 제출

| 항목 | 내용 |
|------|------|
| 트리거 유형 | Google Forms 새 응답 수신 |
| 연동 방식 | Google Sheets (응답 저장) → 새 행 감지 |
| 실행 조건 | 폼이 제출될 때마다 즉시 실행 |

**Google Form 필드 구성:**
```
① 신청자 이름     (단답형)
② 신청자 이메일   (단답형 / 이메일 형식)
③ 도서명          (단답형)
④ 도서 가격 (원)  (숫자형)
⑤ 신청 사유       (장문형, 선택)
```

---

### 🟩 ACTION 1 — 응답 데이터 파싱

| 항목 | 내용 |
|------|------|
| 액션 유형 | 데이터 매핑 / 변수 설정 |
| 입력 | Google Sheets 새 행 데이터 |
| 출력 | name, email, book_title, price 변수 |

```
name       = {{응답[신청자 이름]}}
email      = {{응답[신청자 이메일]}}
book_title = {{응답[도서명]}}
price      = {{응답[도서 가격]}} → 숫자형 변환
```

---

### 🟨 FILTER / ROUTER — 가격 조건 분기

| 항목 | 내용 |
|------|------|
| 조건 | `price >= 50000` |
| YES 경로 | 담당자 승인 요청 이메일 |
| NO 경로 | 신청자 접수 확인 이메일 |

---

### 🟥 ACTION 2-A — 담당자 이메일 발송 (가격 >= 50,000원)

| 항목 | 내용 |
|------|------|
| 액션 유형 | Gmail / SMTP 이메일 발송 |
| 수신자 | manager@company.com (담당자 고정) |
| 제목 | `[승인 요청] 도서 구입 신청 - {{도서명}}` |

**이메일 본문 템플릿:**
```
안녕하세요, 담당자님.

도서 구입 신청이 접수되었습니다. 아래 내용을 확인하시고 승인 여부를 결정해 주세요.

━━━━━━━━━━━━━━━━━━━━━━
📌 신청 정보
  - 신청자: {{name}}
  - 신청자 이메일: {{email}}
  - 도서명: {{book_title}}
  - 도서 가격: {{price}}원
━━━━━━━━━━━━━━━━━━━━━━

※ 50,000원 이상 도서는 담당자 승인이 필요합니다.
승인 시 신청자에게 별도 안내 부탁드립니다.

감사합니다.
[자동 발송 시스템]
```

---

### 🟩 ACTION 2-B — 신청자 이메일 발송 (가격 < 50,000원)

| 항목 | 내용 |
|------|------|
| 액션 유형 | Gmail / SMTP 이메일 발송 |
| 수신자 | `{{email}}` (신청자 이메일, 동적) |
| 제목 | `[접수 완료] 도서 구입 신청이 접수되었습니다` |

**이메일 본문 템플릿:**
```
안녕하세요, {{name}}님.

도서 구입 신청이 정상적으로 접수되었습니다.

━━━━━━━━━━━━━━━━━━━━━━
📚 신청 도서 정보
  - 도서명: {{book_title}}
  - 도서 가격: {{price}}원
━━━━━━━━━━━━━━━━━━━━━━

빠른 시일 내에 구입 후 안내드리겠습니다.
감사합니다.

[자동 발송 시스템]
```

## 4. 구현 도구 비교 (프로젝트 1)

### 🔧 사용 도구
- **도구 A**: n8n (오픈소스 자동화 플랫폼)
- **도구 B**: Make (구 Integromat)

### 📊 비교 분석표

| 비교 항목 | n8n | Make |
|-----------|-----|------|
| **UI/UX** | 노드 기반 캔버스, 개발자 친화적 | 시각적 버블 UI, 직관적 |
| **설정 난이도** | 중간 (초기 설정 필요) | 낮음 (가이드 친절) |
| **조건 분기 방식** | IF Node / Switch Node | Router 모듈 |
| **연동 서비스 범위** | 400+ 노드 (커스텀 가능) | 1,500+ 앱 |
| **무료 플랜** | 셀프호스팅 시 무제한 | 월 1,000 operations |
| **실행 로그** | 각 노드별 상세 입출력 확인 | 시나리오 실행 히스토리 |
| **Google Forms 연동** | Google Sheets 경유 | Google Forms 직접 연동 |
| **이메일 발송** | Gmail Node / SMTP | Gmail / SMTP 모듈 |
| **커스터마이징** | JavaScript 코드 노드 지원 | 제한적 |
| **설치 방식** | 셀프호스팅 or Cloud | Cloud 전용 |

### ✅ 각 도구 장단점

#### n8n
**장점**
- 오픈소스로 셀프호스팅 시 완전 무료
- 코드 노드로 복잡한 로직 구현 가능
- 실행 로그가 노드별로 매우 상세함
- 데이터 변환 유연성 높음

**단점**
- 초기 서버 설정 필요 (Docker 등)
- 일부 노드는 직접 설정이 복잡
- UI가 개발자 친화적이라 비개발자에게 어려울 수 있음

#### Make (Integromat)
**장점**
- 회원가입 후 즉시 사용 가능
- 시각적으로 직관적인 버블 UI
- 1,500개 이상 앱 연동 (Google Forms 직접 지원)
- 비개발자도 쉽게 사용 가능

**단점**
- 무료 플랜 월 1,000 operations 제한
- 복잡한 로직 구현에 한계
- 셀프호스팅 불가

### 💡 도구 선택 가이드

| 상황 | 추천 도구 |
|------|-----------|
| 비용 없이 무제한 사용 원할 때 | **n8n** (셀프호스팅) |
| 빠르게 구축하고 싶을 때 | **Make** |
| 복잡한 로직/코드가 필요할 때 | **n8n** |
| 비개발자가 관리해야 할 때 | **Make** |
| 많은 앱과 연동이 필요할 때 | **Make** |

## 5. 프로젝트 2 — 자유 주제 자동화

### 📌 선정 업무
**도서 구입 신청서 자동 처리** (위 워크플로우와 동일)

### 📌 도구 선정: **Make (Integromat)**

**선정 이유:**
1. Google Forms를 **직접 트리거**로 지원하여 별도 Google Sheets 연동 불필요
2. 회원가입 후 **즉시 사용 가능**하여 구현 속도가 빠름
3. Router 모듈로 **조건 분기를 시각적으로 명확하게** 표현 가능
4. Gmail 모듈이 안정적으로 지원되어 이메일 발송이 간단
5. 비개발자인 담당자도 추후 **직접 수정/관리** 가능

---

## 6. 핵심 개념 정리

### Trigger (트리거)
> 워크플로우를 **시작시키는 이벤트**
> - 본 워크플로우: Google Form 제출 → 즉시 실행

### Action (액션)
> 트리거 이후 **실제로 수행되는 작업**
> - Action 1: 응답 데이터 읽기
> - Action 2-A: 담당자에게 이메일 발송
> - Action 2-B: 신청자에게 이메일 발송

### Filter / Router (조건 분기)
> 조건에 따라 **다른 경로로 분기**시키는 구조
> - 조건: `price >= 50000`
> - YES → 담당자 이메일
> - NO → 신청자 이메일
